# Content Checklist

See `workflows/content-strategy.md`, `workflows/content-optimization.md`, and [[../rules/content-quality]].

## Before recommending new content
- [ ] Genuine search demand evidenced (keyword data, Search Console queries, or clearly reasoned user need)
- [ ] Target search intent identified and matched to the proposed content type (see `workflows/search-intent.md`)
- [ ] Checked for existing pages that already target this intent (avoid cannibalization — see `workflows/keyword-research.md`)
- [ ] Distinct value over what currently ranks articulated concretely, not just "we don't have this yet"
- [ ] Maintainability considered — will this page's facts go stale, and who keeps it accurate?

## Before optimizing existing content
- [ ] Current performance data reviewed if available (Search Console impressions/clicks/position — see `workflows/search-console.md`)
- [ ] Actual search intent for the page's current/target query reconfirmed (intent can drift from what the page was originally written for)
- [ ] Gaps identified relative to what's currently ranking (not just competitor word count)
- [ ] Existing voice/tone preserved (see [[../rules/content-quality]])

## Quality bar (every piece of content, new or edited)
- [ ] No fabricated statistics, claims, credentials, or authority signals (see [[../rules/no-fabrication]])
- [ ] No keyword stuffing or unnatural repetition (see [[../rules/no-black-hat]])
- [ ] No padding for word count
- [ ] Headings reflect real content sections (see `checklists/on-page-checklist.md`)
- [ ] Internal links added are genuinely relevant, not forced (see `checklists/internal-linking-checklist.md`)
- [ ] If author/expertise info is surfaced, it's real (see [[../rules/no-fabrication]])

## Scale checks (multiple pages / programmatic content)
- [ ] Each page individually clears the quality bar above — no page riding on the credibility of the set
- [ ] Uniqueness threshold met beyond template variable substitution (see `workflows/programmatic-seo.md`)
- [ ] Real, page-specific data backs any generated content (not filler prose around a single data point)

## Output
- [ ] Recommendations logged in `templates/content-roadmap.md`, prioritized per the standard Severity/Impact/Effort/Risk framework
